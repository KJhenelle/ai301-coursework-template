# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The diff's changed files and hunks read against the plan's scope (in / not-in), files, and approach, plus any deviation notes; and the description's claims about what changed read against the diff. | Pass if every changed file and behavior change in the diff falls inside the plan's scope or is covered by a stated deviation note, the plan's central change is actually present in the diff, and the description claims nothing the diff does not deliver (and omits nothing material the diff does). Fail if the diff changes something the plan puts out of scope or never mentions (more), leaves out a piece of the plan's change with no note (less), or the description claims fidelity or coverage the diff contradicts. A deviation honestly noted in plan.md or the description and consistent with the diff is NOT drift. Unclear only if no plan scope is in the package. | required |
| test-evidence | The test-evidence section read against the plan's test plan and the repro's own steps and observed-before behavior; and the outcome of the repo's own checks or suite shown there. | Pass if the evidence re-runs the repro's own inputs (or a named test that exercises the changed path), shows an observed-before and an observed-after that differ in the way the plan's expected-after says, and shows the repo's own test suite or checks run with their outcome visible (a failing check with an honest reason and nothing hidden still passes). Fail if the evidence is only "tests pass" with no command, test name, or count; exercises a path the diff did not change or that behaves the same before and after; omits the before or the expected-after; or never shows the repo's own checks run. Unclear only if the package has no test-evidence section to read. | required |
| diff-reviewability | The unified diff's file list and hunks, and the commit list; live mode also `git status` for working notes. | Pass if every hunk is part of the change the plan describes, with no debug prints, commented-out or dead code, formatting-only churn, unrelated drive-by edits, working notes (plan.md, pr_draft.md, test_evidence.md), build artifacts, or lockfile noise riding along, so a reviewer can see the fix at a glance. Fail if any such debris or unrelated hunk is in the diff or commits. Judge the content of the hunks, not the number of files or commits. Unclear only if the diff is absent. | required |
| template-and-standards | The repo-facts block's stated PR-template asks and contribution rules (live: `.github/PULL_REQUEST_TEMPLATE.md` and CONTRIBUTING.md), read against the description and the diff; plus explicit maintainer direction in the thread. | Pass if every section or ask the repo states for a PR is honored with real content (not blank, placeholder, or boilerplate), including any item the template asks for that lives in the diff (a changelog, whatsnew, test, or docs entry; a closing-issue reference), and nothing a maintainer asked for in the thread is ignored. Fail if a stated template section or checklist is visibly ignored or left as boilerplate, or a stated required file entry is absent from the diff, or a maintainer's explicit direction is ignored. Unclear only if the package states no template or policy and the description otherwise names the issue. | required |
| ai-disclosure | The repo-facts block's stated AI-use policy (live: CONTRIBUTING.md and the template's disclosure section), read against the description. | Pass if, where the repo states an AI-use policy or the template has a disclosure section, the description contains an explicit disclosure of AI assistance in the form the policy asks (naming the tool or extent only where the policy requires it, and honoring any restriction it sets); where the repo states no AI policy and has no disclosure section, pass with no disclosure needed. Fail if a stated policy or disclosure section exists and the description has no disclosure, or the disclosure is empty boilerplate, or the PR does what the policy forbids. In live mode, scope.md's house rule applies: this course work is AI-assisted, so disclosure is always required. Unclear only if the package does not say whether a policy exists AND the description has no disclosure. | required |

## Verdict rule

Accept if every check passes. Reject if any check is fail. `unclear` counts as fail: a package whose readiness cannot be verified is not ready to submit. All five checks are required; none is preferred. A PR that honestly discloses a shortfall (a deviation note, an honest failing-check note with its reason) can still pass every check. In the output, quote the evidence of the first failing check in the order listed above as the deciding fact.
